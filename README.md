# موقع النور سكان (EL Nour Scan)

موقع عربي (RTL) لرعاية طبية منزلية متكاملة داخل الإسكندرية.
مبني بـ Next.js (App Router) وTypeScript وTailwind CSS.

## التشغيل

يتطلب Node.js بإصدار 20.9 أو أحدث.

```bash
npm install
npm run dev      # التطوير على http://localhost:3000
npm run lint     # فحص الكود
npm run build    # بناء نسخة الإنتاج
npm start        # تشغيل نسخة الإنتاج بعد البناء
```

## وضع الديمو

الموقع دلوقتي في مرحلة بناء الواجهة، وفيه بيانات تجريبية: الفريق، التراخيص، الأسعار، التقييمات، المناطق، الأرقام، المقالات، 19 خدمة، وحساب المريض.

- البيانات دي في `src/config/demo.ts` و`demo-services.ts` و`articles.ts`.
- كل صفحة فيها شريط «نسخة تجريبية»، والموقع ممنوع من الفهرسة، والديمو مش بيدخل في JSON-LD.
- **حساب المريض شكل بس:** مفيش تسجيل دخول ولا حجز ولا دفع ولا رسايل حقيقية.

**للإطلاق:** اضبط `NEXT_PUBLIC_DEMO_MODE=false`. ده بيشيل الشريط وكل الديمو وصفحاته، ويرجع الفهرسة. انقل قبلها البيانات الحقيقية إلى `site.ts` وملفات الخدمات.

## أين أعدّل؟

| المطلوب | الملف |
| --- | --- |
| الاسم، الأرقام، واتساب، العنوان، ساعات العمل، المناطق، الروابط، التحليلات | `src/config/site.ts` |
| خدمات الأشعة والفحوصات | `src/config/services.ts` |
| خدمات الرعاية (أطباء، تمريض، تحاليل...) | `src/config/care-services.ts` |
| الأقسام، برامج الرعاية، وخدمات «قريبًا» | `src/config/care.ts` |
| أسئلة الصفحة الرئيسية | `src/config/faqs.ts` |
| الألوان والخطوط | `src/app/globals.css` و`src/app/layout.tsx` |
| صورة القسم الافتتاحي | `src/assets/home-visit.jpg` |
| نصوص قسم النموذج 3D في الرئيسية | `src/components/XrayModel3D.tsx` |
| أشكال وألوان النموذج 3D | `src/components/xray-scene.ts` |
| صورة المشاركة على السوشيال | `public/og.png` (مقاس 1200×630) |

أي حقل فاضي في `site.ts` يختفي من الواجهة ومن JSON-LD. عند تعبئته يظهر تلقائيًا.
اكتب المعلومات المؤكدة من إدارة المركز فقط.

- **المناطق:** `areas: ["اسم الحي"]`. وطالما القائمة فاضية، الموقع يدعو الزائر للسؤال عن منطقته.
- **العنوان:** لازم تملأ `address.street` عشان يظهر العنوان.
- **ساعات العمل:** `openingHours: [{ label: "يوميًا من 9 صباحًا إلى 9 مساءً", schema: "Mo-Su 09:00-21:00" }]`.
- **واتساب:** `whatsapp.phone` هو رقم الأزرار العامة، و`whatsapp: false` داخل `phones` يخفي رابط واتساب من جوار الرقم.
- **الأرقام:** موبايل مصري من 11 رقمًا. الرقم غير الصحيح يوقف البناء برسالة خطأ بدل نشر رابط معطل.

## متغيرات البيئة

انسخ `.env.example` إلى `.env.local` أو أضف المتغيرات في لوحة الاستضافة:

| المتغير | الوظيفة |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | النطاق النهائي، مثل `https://example.com`. مطلوب قبل النشر الفعلي |
| `INQUIRY_WEBHOOK_URL` | اختياري: رابط يستقبل استفسارات النموذج |

أعد البناء بعد تغيير أي متغير.

**بدون نطاق:** `sitemap.xml` يكون فارغًا، ولا تُولَّد روابط canonical أو BreadcrumbList. هذا مقصود حتى لا تُنشر روابط مفترضة.

## نموذج التواصل

- **بدون Webhook (الوضع الحالي):** النموذج يتحقق من البيانات ويجهّز رسالة واتساب يرسلها الزائر بنفسه. لا يصل شيء إلى خادم الموقع.
- **مع `INQUIRY_WEBHOOK_URL`:** النموذج يرسل إلى `/api/inquiry`، والمسار يتحقق من البيانات ويرسل JSON عبر POST إلى الرابط. مناسب لأدوات مثل Make أو Zapier أو CRM.

```json
{ "name": "", "phone": "", "service": "", "area": "", "message": "" }
```

المسار لا يخزّن البيانات، ولا يوجد نظام حجز، لذلك لا يقول الموقع للزائر إن الحجز تم.
قبل تفعيل Webhook أضف حدًا لمعدل الطلبات (rate limiting) من الاستضافة أو أداة مثل Cloudflare، لأن الحماية الحالية هي حقل مصيدة فقط.

## النشر

**Vercel:** اربط المستودع، وأضف `NEXT_PUBLIC_SITE_URL`، ثم انشر.

**استضافة عادية (Hostinger public_html):** نسخة HTML ثابتة من غير Node.

```bash
NEXT_PUBLIC_SITE_URL=https://elnourscan.com npm run build:static
```

- الناتج في مجلد `out/`. ارفع **محتواه** (مش المجلد نفسه) جوه `public_html`، ومعاه `.htaccess`.
- طلب الخدمة في النسخة الثابتة بيشتغل بواتساب، ومسار `/api/inquiry` مش موجود فيها.
- فعّل SSL و«Force HTTPS» من لوحة Hostinger.

**أي استضافة Node.js:**

```bash
npm ci
NEXT_PUBLIC_SITE_URL=https://example.com npm run build
npm start
```
